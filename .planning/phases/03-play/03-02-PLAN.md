# Plan 03-02: Proximity Preloading & Seamless Layer Swap Algorithm

## Goal
Implement a highly responsive, frame-accurate proximity-based preloading algorithm and a double-buffered transition sequence. By scheduling layer adjustments within browser requestAnimationFrame intervals and locking background audio states, the engine delivers instant node transitions (<50ms delay) with zero visual glitches or audio pops.

## Must Haves (must_haves)
- [ ] `must_have_01`: Connect Foreground player's `timeupdate` handler to drive `NodeStateManager.tick()` and monitor the proximity window.
- [ ] `must_have_02`: Trigger background preloading exactly 5 to 8 seconds prior to the end of the node or interactive choice timestamp.
- [ ] `must_have_03`: Prevent re-entrant network requests by locking preloading status via `preloadedNodeIdRef`, resetting it only when a `nodeChanged` event fires.
- [ ] `must_have_04`: Prioritize next node selection logic: Default timeout path (`defaultNextNodeId`) first, followed by the first interaction option (`interactions[0].options[0].targetNodeId`).
- [ ] `must_have_05`: Apply the Explicit Mute Lock (`muted = true`, `volume = 0`) to the background player during its loading phase.
- [ ] `must_have_06`: Perform layer switching inside a microtask queue using `requestAnimationFrame`, swapping z-index (20/10), opacity (1/0), and pointer-events (auto/none) in <50ms.
- [ ] `must_have_07`: Smooth out audio transitions during swapping via a 120ms linear audio fade-in to eliminate click/pop noise artifacts.
- [ ] `must_have_08`: Gracefully handle Autoplay constraints: catch `play()` promise rejections, downgrade to muted autoplay, and present a UI volume unlock prompt.
- [ ] `must_have_09`: Integrate Preemption recovery: If a user selects a non-preloaded node, immediately cancel background load via `.unload()`, begin hot-loading the selected branch, and show a temporary glassmorphism loading container.
- [ ] `must_have_10`: Implement a React `hasStarted` state and a high-quality "Start Experience" overlay button, triggering the initial Foreground video play sequence in a synchronous handler to unlock modern browser autoplay policies.
- [ ] `must_have_11`: Implement thorough cleanup of `nodeStateManager` subscriptions (`nodeChanged`, etc.) using `.off(...)` inside React `useEffect` cleanups to block listener leakage under StrictMode.
- [ ] `must_have_12`: Build an 8-second preloading timeout guard. When the preloading process exceeds 8 seconds without a resolved ready state, abort the visual hot-swap transition, showing a loading glass overlay instead and triggering preemption hotloading.

## Tasks

<task id="03-02-01" name="Implement Proximity-Based Preloading, Priority Selection, and Listener Cleanup">
Implement the trigger loop that watches Foreground time updates and initiates silent background preloading based on priority routing.

### Detailed Steps:
1. Attach a `timeupdate` listener to the active Foreground player in `InteractivePlayer.tsx`.
2. Within the listener:
   - Call `nodeStateManager.tick(currentTime)` to keep the core engine state synchronized.
   - Calculate remaining time: `const timeRemaining = duration - currentTime`.
   - Check if `timeRemaining` is between 5.0 and 8.0 seconds, or if it is nearing the next interactive timestamp.
3. Establish a re-entrancy lock check:
   - Ensure a ref `preloadedNodeIdRef = useRef<string | null>(null)` tracks the node currently preloaded.
   - If a preload has already been dispatched for this node's successors, skip additional calls.
4. Retrieve the next candidates list using `nodeStateManager.getPreloadCandidateNodeIds()`.
5. Select a single candidate node to load based on priority:
   - If `currentNode.defaultNextNodeId` exists, choose it as the primary candidate.
   - Otherwise, select the first option target: `currentNode.interactions[0].options[0].targetNodeId`.
6. Load the chosen video stream into the Background Shaka Player instance. Keep the element muted and its volume set to zero.
7. Record the preloaded node's ID in `preloadedNodeIdRef.current`.
8. Subscribe to `nodeStateManager.on('nodeChanged', ...)` to reset `preloadedNodeIdRef.current = null` upon node change to prepare for the next cycle.
9. **Event Cleanups 防线**: Ensure that every subscription made to `nodeStateManager` (e.g. `nodeChanged` or `interactionTriggered` events) returns a thorough cleanup function in its mounting `useEffect` calling `nodeStateManager.off('nodeChanged', callback)`, preventing memory leaks and duplicate handler bindings during React StrictMode double mounts.

### Verification Criteria:
- Verify TS compiler checks pass.
- In the browser console, play a video and ensure the log prints the preloading trigger exactly once, 5-8 seconds before the node ends.
- Validate in code that all `on` event listeners are completely paired with a corresponding `off` call inside the `useEffect` unmount cleanup.
</task>

<task id="03-02-02" name="Implement Seamless Layer Swapping, Audio Cross-fade, Autoplay Start Overlay, and Timeout Failsafe">
Create the seamless transition scheduler that performs the physical swap on choice execution and integrates fail-safe fallbacks.

### Detailed Steps:
1. **Start Experience Overlay Lock**:
   - Define a React State `const [hasStarted, setHasStarted] = useState(false)` at the top of `InteractivePlayer.tsx`.
   - If `hasStarted` is `false`, render a beautiful, responsive visual overlay blocking the viewport with a "开始剧情 / 体验" (Start Experience) button.
   - When clicked, synchronously call `.play()` on the Active Player ref inside the click event thread. This registers a valid User Activation Gesture with the browser, completely unlocking subsequent autoplay and volume restrictions. Set `hasStarted(true)`.
2. **8-Second Timeout Failsafe**:
   - Introduce a ref `preloadTimeoutRef = useRef<NodeJS.Timeout | null>(null)`.
   - When preloading begins (Task 03-02-01), schedule an 8-second timer: `preloadTimeoutRef.current = setTimeout(() => { ... }, 8000)`.
   - Listen for background load completion (e.g., Shaka's `canplaythrough` or buffering resolved event). If resolved before 8 seconds, clear the timer: `clearTimeout(preloadTimeoutRef.current)`.
   - If the timer triggers, flag the preloading status as failed / timed out (`isPreloadTimedOutRef.current = true`).
3. Write the main transition coordinator function: `executeSeamlessTransition(targetNodeId: string)`.
4. Handle preload correctness and timeout:
   - Check if `targetNodeId === preloadedNodeIdRef.current` AND `isPreloadTimedOutRef.current` is `false`.
   - **Preloading Successful**: Proceed with the instant transition sequence.
   - **Mismatch or Timeout Preemption**: If the preload failed, timed out, or user picked a different path:
     - Clear the timeout: `clearTimeout(preloadTimeoutRef.current)`.
     - Cancel the visual seamless swap (do NOT swap z-indexes yet).
     - Immediately invoke `.unload()` on the background Shaka player.
     - Show a high-quality glassmorphism loading skeleton overlay across the viewport.
     - Hotload the targeted branch video into the background player and await buffer readiness before executing the final swap.
5. Transition execution sequence:
   - Call `.play()` on the background player. Wait for the play promise to resolve.
   - Inside `requestAnimationFrame`, swap DOM layers:
     - New Foreground (former background): set `style.zIndex = '20'`, `style.opacity = '1'`, `style.pointerEvents = 'auto'`.
     - New Background (former foreground): set `style.zIndex = '10'`, `style.opacity = '0'`, `style.pointerEvents = 'none'`.
   - Set Explicit Mute Lock on the new background: set `muted = true`, `volume = 0`, call `.pause()`, and reset `currentTime = 0`.
   - Trigger volume fade-in on the new foreground: unmute and gradually scale volume from 0 to global volume over 120ms using a smooth linear step interval.
   - Swap the active role tag refs: `activePlayerRef.current = newActiveRole`.
6. Wrap all `.play()` calls in try/catch blocks:
   - Catch modern browser autoplay blocks (`NotAllowedError`).
   - If blocked, force `muted = true`, begin muted autoplay, and present a float unmuting overlay to prompt user activation gesture.

### Verification Criteria:
- Run `npx tsc --noEmit` and verify there are no compilation errors.
- Perform a manual click test through sandbox nodes. Verify the transition is instantaneous without screen flickering, black frame flashes, or audio leaks.
- Verify that a beautiful "Start Experience" overlay is rendered first, and clicking it unlocks initial playback.
- Verify the timeout mechanism: Mock a slow network request exceeding 8 seconds, click a branching option, and verify that the glassmorphism loading skeleton displays instead of a frozen frame, subsequently completing transition successfully.
</task>
