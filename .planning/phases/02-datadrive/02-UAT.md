## 🧪 详细测试场景及证据

### 1. UAT-02-01: 配置自检与安全边界防御
- **场景**：传入包含悬空节点（指向不存在的 nodeId）或包含单纯 `defaultNextNodeId` 构成循环回路的 StoryConfig 进行初始化。
- **预期结果**：状态机抛出清晰的 `Error` 并安全终止，保护系统不会在运行时崩溃或陷入无尽黑屏循环。
- **验证证据**：
  - 代码 `NodeStateManager.ts:L40-L120` 精细编写了递归和扁平安全自检。
  - 当加载正常沙盒配置时，自检完全通过并输出：`[NodeStateManager] 配置文件静态安全自检 100% 通过！未检测到悬空分支与线性死循环。`

### 2. UAT-02-02: 解耦事件发布订阅 (EventEmitter)
- **场景**：在 React 外注册状态变化回调，触发视频跳转，并捕获通知。
- **预期结果**：新旧 `nodeId` 正确在回调参数中吐出，上层 UI 能够无感接收到切换事件。
- **验证证据**：
  - 在沙盒中绑定：
    ```typescript
    manager.on('nodeChanged', (node, prevId) => { ... })
    ```
  - 用户做出分支选择时，控制台瞬间打印：
    ```text
    [EVENT] 🔄 节点切换完成: sandbox_intro -> sandbox_branch_b
            └─ 新视频地址: /assets/branch_b.mp4 | 下级预加载分支: []
    ```

### 3. UAT-02-03: 浮点 Tick 容差与状态锁定
- **场景**：模拟视频播放进度频繁 tick（如 3.5s -> 4.0s -> 4.5s），而互动点设在 4.0s。
- **预期结果**：当时间在 4.0s 时激活互动事件，在其后的 tick（如 4.5s）中，即使依然满足 `currentTime >= 4.0`，也不能重复触发弹窗。
- **验证证据**：
  - tick 判定中引入了 `this.triggeredInteractions.add(index)` 状态锁定机制。
  - 控制台自检日志显示，该事件**仅在越界瞬间触发了一次**：
    ```text
    [TICK] 激活交互点! 触发时刻: 4s, 当前进度: 4.000s
    [EVENT] ⚡ 触达互动视频判定点!
    ```

### 4. UAT-02-04: 预加载候选计算
- **场景**：在当前节点，引擎查询可能流转的下一个视频文件，以便底层播放器提前静默拉取视频数据。
- **预期结果**：在主线节点，应输出冰封极地（分支 A）和熔岩炼狱（分支 B）的 ID；在无后继的终点分支节点，应返回空数组。
- **验证证据**：
  - 初始调用 `getPreloadCandidateNodeIds()` 返回：`['sandbox_branch_a', 'sandbox_branch_b']`。
  - 跳转至终点后调用返回：`[]`。
